# ECCO v4r4 override trees vs MITgcm checkpoint66g

Audit of `ECCO-v4-Configurations/ECCOv4 Release 4/code/` ("full", V4r4 as run) and `.../flux-forced/code/`
("ff") against `~/MIT/MITgcm_c66g`, written 2026-09-23 (plan Task 2). The two tables at the end are generated by
`scripts/audit_overrides.py`; `scripts/tests/test_overrides.py` fails if they are stale or if a changed file has no row
in the classification table. Line numbers refer to the override file unless a path says otherwise.

Counts in the inventory: "code (raw)" changed lines vs the c66g file, where "code" excludes Fortran comment and blank
lines. 79 files; 77 differ from c66g (2 are byte-identical copies: `cost_generic.F`, `ctrl_init_rec.F`).

## Findings

### Forward physics: full V4r4 vs c66g
Only one override changes forward values:

1. **Gibraltar ×10 harmonic viscosity** — `code/mom_calc_visc.F:413–419` (D points, `yC`∈[33,39], `xC`∈[−7,−2],
   `viscAh_D = 10._d0*viscAh_D`) and `:523–529` (Z points, same box on `yG`/`xG`). Applied **after** the
   Min/Max clipping of `viscAh_D`/`viscAh_Z`; the biharmonic coefficients are not scaled. Identical in both trees.

Overrides that change code but not forward values in V4r4 (each needs one confirmation in the Task 5 dumps):

2. `mom_calc_visc.F:406,425,516,535` — `viscFacAdj` now multiplies all four 3-D viscosity fields (c66g:
   `viscAhDfld`, `viscA4Dfld` only, `pkg/mom_common/mom_calc_visc.F:413,427`). Forward `viscFacAdj = 1`
   (`model/src/set_defaults.F:131`; the forward `AUTODIFF_INADMODE_SET/UNSET` are empty routines,
   `pkg/autodiff/autodiff_inadmode_unset.F`). It matters only in the TAF reverse sweep
   (`viscFacAdj = viscFacInAd`, `pkg/autodiff/autodiff_inadmode_set_ad.F:53`; back to 1 in
   `autodiff_inadmode_unset_ad.F:53`) — the
   JAX `viscFacInAd` seam (plan Task 17) must scale **all four** fields, as this override does.
3. `mom_calc_visc.F` drops the deep-atmosphere factors (`deepFac2C`, `deepFac3/4`, `recip_deepFacC`); all are 1
   when `deepAtmosphere=F` (`model/src/set_grid_factors.F:52,54`).
4. `initialise_varia.F:166–186` (`CALC_PHI_RLOW_INI`): integrates `CALC_PHI_HYD` once at start-up so `phiHydLow` is
   non-zero at the first `ECCO_PHYS` call. In c66g forward physics `phiHydLow` is only written by
   `DIAGS_PHI_RLOW` and read by diagnostics / `pkg/ecco` (`m_bp`); it does not enter the prognostic state.
   (CATALOG.md listed it as a forward change; it is a cost/diagnostic change.)
5. `ctrl_map_ini_genarr.F:107–108` initialises `igen_uvel0/igen_vvel0` to 0 (c66g leaves them undefined,
   `pkg/ctrl/ctrl_map_ini_genarr.F:60`). V4r4 `data.ctrl` lists both `xx_uvel` and `xx_vvel`, so the loop sets them
   either way: the u/v initial-condition controls are applied in both trees (with `ALLOW_UVEL0/VVEL0_CONTROL`).
6. `rotate_uv2en.F` (loop bounds/halo handling rewritten): on the forward path only to add `xx_uwind/xx_vwind`
   controls (`pkg/exf/exf_getffields.F:603,739`, `ALLOW_ROTATE_UV_CONTROLS`); V4r4 `data.ctrl` has no such
   control and flux-forced's forcing controls are all zero. Otherwise called from `ecco_phys`/cost only.

**Consequence:** the forward-physics differences between c66g and V4r4 sit almost entirely in **CPP options**
(generated table below) and **namelists**, not in overridden source. The forward-relevant macros are:
`NONLIN_FRSURF` (+ r* code on, sigma code off), `ALLOW_ADAMSBASHFORTH_3`, `SHORTWAVE_HEATING`,
`ALLOW_GEOTHERMAL_FLUX`, `ALLOW_3D_DIFFKR`, `ALLOW_BALANCE_FLUXES/RELAX`, `SOLVE_DIAGONAL_KINNER` (solver
variant), `ALLOW_SRCG` off, `ALLOW_3D_VISCAH/VISCA4`, `ALLOW_GGL90_SMOOTH`, `GM_BOLUS_BVP` off,
`GMREDI_WITH_STABLE_ADJOINT`, `GM_EXCLUDE_{CLIPPING,FM07_TAP,AC02_TAP,SUBMESO}`, `ALLOW_KAPGM/KAPREDI_3DFILE`;
EXF (full only): `ALLOW_BULK_LARGEYEAGER04`, `ALLOW_ZENITHANGLE`, `USE_EXF_INTERPOLATION`; sea ice (full only):
`SEAICE_ALLOW_FREEDRIFT`, `SEAICE_ALLOW_CLIPVELS`, no JFNK/Krylov.

### `ALLOW_AUTODIFF` is defined in the forward build
`packages.conf` (identical in both trees) compiles `autodiff`, `ctrl`, `cost`, `ecco`, `grdchk`, `smooth`. With the
package compiled, `ALLOW_AUTODIFF` is defined in **every** executable of this configuration, and c66g takes
different forward branches under it, e.g.:
- `model/src/forward_step.F:418–450`: `RESET_NLFS_VARS` and `UPDATE_R_STAR(.FALSE.)` run **every step**
  (without AUTODIFF only `IF (doResetHFactors)`).
- `model/src/do_oceanic_phys.F:286–298`: `saltPlumeDepth`/`saltPlumeFlux` zeroed at the start of each step.
- `model/src/dynamics.F:327–328`: `phiHydLow` zeroed each step; `forward_step.F:800–812`: `momStepping` guards removed.

**For Task 4/5:** the Fortran oracle must be built with the full `packages.conf` (autodiff included) even for forward
runs, and the JAX port must follow the `ALLOW_AUTODIFF` branches. Task 5's gcov run lists which ones execute.

### Flux-forced tree vs full V4r4
Forward-relevant:
1. **Salt-plume flux read from file** (`READIN_SALT_PLUME_FLUX`, `EXF_OPTIONS.h:189`): new EXF field `spflx`
   (`EXF_FIELDS.h:297–302`, `EXF_PARAM.h`, `exf_readparms.F`, `exf_init_fixed.F:333–345`,
   `exf_init_varia.F:380–391`, read each step `exf_getffields.F:460–474`, xx control `:750–754`), copied to
   `saltPlumeFlux` in `exf_mapfields.F:343–349` plus `_EXCH_XY_RS` at `:386–388`; `do_oceanic_phys.F:293–295` no
   longer zeroes `saltPlumeFlux`. The flux is then used by the unchanged c66g salt-plume path
   (`SALT_PLUME_DO_EXCH` `do_oceanic_phys.F:581`, `SALT_PLUME_CALC_DEPTH` `:949`; `SALT_PLUME_VOLUME` undefined,
   `pkg/salt_plume/SALT_PLUME_OPTIONS.h:27`). `exf_inscal_spflx` not set in `data.exf` ⇒ 1.0 (`exf_readparms.F`).
2. `ALLOW_ATM_TEMP` undefined (`EXF_OPTIONS.h:168`): bulk formulae compiled out; fluxes read directly
   (`hflux, swflux, ustress/vstress (C grid), sflux, saltflx, spflx, apressure`), 6-hourly from 19920101 03:00.
3. `useSeaice=F`, no `useDiagnostics`, no `useProfiles` in `flux-forced/namelist/data.pkg` (seaice still compiled).
   `SEAICE_FAKE` runs only if `SEAICEadjMODE = -1` (`do_oceanic_phys.F:383`); `SEAICEadjMODE` is set by
   `SEAICE_READPARMS`, which does not run when `useSEAICE=F` — verify in the gcov run that `SEAICE_FAKE` is not called.
4. The time-varying forcing controls (`xx_qnet … xx_spflx`, `flux-forced/namelist/data.ctrl:31–96`) are all
   zeros (adjustments are folded into the forcing files; `flux-forced/doc/README_fluxforced.md`), so they add 0.

5. **Namelist:** ff `data` sets `temp_EvPrRn = 0.` (PARM01; unset in full V4r4) — the temperature assigned to
   evaporation/precipitation/runoff with `useRealFreshWaterFlux=T`. Forward-relevant; port from the run's `data`.
   Also ff `data.autodiff` has `useSALT_PLUMEinAdMode = .TRUE.` (full: `.FALSE.`): the two trees' ECCO-mode backward
   semantics differ for salt plume (Task 17). ff `data.ctrl` sets every `mult_genarr*/mult_gentim2d = 0.` (cost
   weights only). Other shared namelists (`data`, `data.gmredi`, `data.ggl90`, `data.salt_plume`, `data.cal`,
   `data.exch2`, `eedata`, `data.smooth`) are identical in content (checked with `mitgcm_jax/io/namelist.py`).

Not forward-relevant: `INCLUDE_PLOADBAR` (cost only), `BOXMEAN_COST_ONLY`, ECCO pickups for the steric reference
(`ecco_read/write_pickup.F`, `ecco_init_varia.F`), gentim2d record offsets (`ctrl_init.F:917`,
`ctrl_map_ini_gentim2d.F`, `ctrl_cost_gen.F`), TAF checkpoint levels (`tamc.h`: full 5/220/220, ff 25/100/100).
`exf_monitor.F:207` adds an `_spflx` %MON line and fixes `EXF_SALTFLX`→`ALLOW_SALTFLX`: the ff monitor output has
more lines than the full one.

### Plan corrections
The plan (Task 2, Task 14b, 16b) assumed the ff overrides of `apply_forcing.F`, `impldiff.F`, `mom_vecinv.F`,
`mom_vi_hdissip.F`, `momentum_correction_step.F` change the physics. They do not: all five only add momentum-budget
diagnostics (`Um_Wind`, `Um_Impl`, `UBotDrag`, `Um_dKEdx`, `Um_Diss2/4`, `Um_dPsdx`, "HP" comments), and
`useDiagnostics` is off in the ff run. The JAX port follows the c66g versions of these routines for both trees.
`forward_step.F` differs from c66g only by a TAF `CADJ STORE` (`:1010–1013`) and, in ff, the `ECCO_PHYS` argument
list (`:1189`). Note: `impldiff.F` (ff) leaves `diagNamb` undefined for tracers (`tracerId ≥ 1`) and evaluates
`DIAGNOSTICS_IS_ON(diagNamb)` — harmless with diagnostics off, but do not enable diagnostics in ff reference runs
without checking this.

### Reader notes
- `mdsio_read_meta.F` (full only) reads `nrecords` with `I6` (c66g `I5`); ff overrides only the writer. Our `.meta`
  reader must accept 6-digit record counts.
- `CPP_EEOPTIONS.h` is not overridden: c66g defines `GLOBAL_SUM_ORDER_TILES`
  (`eesupp/inc/CPP_EEOPTIONS.h:132`) — global sums are ordered by tile, so 96×(30×30) and 13×(90×90) runs differ
  in summation order (part of the Task 4 spread).
- Options headers used unmodified from c66g for compiled packages include `GAD_OPTIONS.h`, `SALT_PLUME_OPTIONS.h`,
  `MOM_VECINV_OPTIONS.h`, `CAL_OPTIONS.h`, `SMOOTH_OPTIONS.h`, `COST_OPTIONS.h`, `CPP_EEOPTIONS.h`.
